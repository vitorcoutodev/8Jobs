8JOBS — EXPLICAÇÃO DO PROJETO

Este guia descreve o código atual do 8Jobs: uma plataforma web de vagas feita com
React no frontend, Node.js e Express no backend, quatro microserviços e quatro
bancos MongoDB separados.


1. VISÃO GERAL

Candidatos consultam vagas e enviam candidaturas. Empresas cadastram seus dados
e publicam oportunidades. O frontend envia pedidos HTTP ao gateway; o gateway
encaminha cada pedido ao microserviço responsável; o serviço valida os dados e
acessa o banco que lhe pertence.

                 FRONTEND (React)
                        |
                        | HTTP / JSON
                        v
                 GATEWAY (:3000)
                        |
       +----------------+----------------+----------------+
       |                |                |                |
       v                v                v                v
   EMPRESAS          VAGAS          CANDIDATOS      CANDIDATURAS
   API :3001         API :3002       API :3003        API :3004
       |                |                |                |
       v                v                v                v
   8jobs_empresas   8jobs_vagas   8jobs_candidatos  8jobs_candidaturas

As setas verticais representam cada serviço acessando o próprio banco. Os
bancos não consultam uns aos outros diretamente. Quando um serviço precisa de
informação de outro, ele consulta a API desse serviço usando HTTP.


2. COMO OS SERVIÇOS SE COMUNICAM

Vagas e empresas

1. O serviço de vagas recebe uma vaga com empresaId.
2. Antes de criar ou trocar a empresa de uma vaga, consulta a API de empresas.
3. A API de empresas lê o banco 8jobs_empresas e responde com os dados da empresa.
4. O serviço de vagas guarda o empresaId no banco 8jobs_vagas. Nas consultas,
   também pode incluir os dados da empresa na resposta.

Candidaturas, candidatos e vagas

1. O serviço de candidaturas recebe candidatoId e vagaId.
2. Consulta a API de candidatos para confirmar que o candidato existe.
3. Consulta a API de vagas para confirmar que a vaga existe e está ABERTA.
4. Verifica se o candidato e a vaga existem e se a vaga está aberta.
5. Se as validações passarem, grava candidatoId e vagaId no banco 8jobs_candidaturas.
6. O mesmo candidato não pode se candidatar duas vezes à mesma vaga.,


Esse fluxo está implementado em:

- services/vagas/src/clients/empresasClient.js
- services/candidaturas/src/clients/clienteHttp.js
- services/vagas/src/controllers/vagasControllers.js
- services/candidaturas/src/controllers/candidaturaControllers.js

O gateway é o ponto de entrada do frontend. Ele não substitui essas chamadas
entre serviços: as validações de empresa, candidato e vaga são feitas pelos
próprios microserviços.


3. FRONTEND

O frontend está em frontend/ e usa React, Vite, React Router e Tailwind CSS.
O Vite serve a interface durante o desenvolvimento; ele não é o backend nem o
banco de dados.

As páginas estão ligadas às rotas abaixo:

- / — página inicial, que consulta e filtra vagas.
- /vagas — lista de vagas.
- /vagas/:id — detalhes de uma vaga.
- /vagas/cadastrar — cadastro de vaga.
- /cadastro-empresa — cadastro de empresa.
- /cadastro-candidato — cadastro de candidato.
- /candidatos — lista de candidatos.
- /formulario — formulário de candidatura.

frontend/src/services/api.js define o endereço base da API. Por padrão, usa
http://localhost:3000/api. A variável VITE_API_URL pode substituir esse endereço.
Os demais arquivos de frontend/src/services/ agrupam os pedidos para cada
recurso, como vagas, empresas, candidatos e candidaturas.


4. BACKEND E ROTAS

O backend usa Node.js e Express. Em cada serviço, as rotas recebem os pedidos,
os controllers aplicam as regras, os models definem os dados e o Mongoose lê ou
grava no MongoDB.

Gateway — server.js, porta 3000

Recebe os pedidos públicos em /api e encaminha /api/empresas, /api/vagas,
/api/candidatos e /api/candidaturas para o serviço correspondente. Os endereços
internos podem ser ajustados pelas variáveis EMPRESAS_URL, VAGAS_URL,
CANDIDATOS_URL e CANDIDATURAS_URL.

Microserviços e rotas

- Empresas — porta 3001; GET /empresas, GET /empresas/:id, POST /empresas,
  PUT /empresas/:id e DELETE /empresas/:id.
- Vagas — porta 3002; GET /vagas, GET /vagas/:id, POST /vagas,
  PUT /vagas/:id e DELETE /vagas/:id.
- Candidatos — porta 3003; GET /candidatos, GET /candidatos/:id,
  POST /candidatos, PUT /candidatos/:id e DELETE /candidatos/:id.
- Candidaturas — porta 3004; GET /candidaturas, GET /candidaturas/:id,
  POST /candidaturas, PUT /candidaturas/:id e DELETE /candidaturas/:id.

O gateway acrescenta /api ao endereço público. Por exemplo, o frontend pede
GET http://localhost:3000/api/vagas; o gateway encaminha para
GET http://localhost:3002/vagas.


5. DADOS E REGRAS PRINCIPAIS

Cada serviço tem seu próprio banco e coleção:

- Empresas: banco 8jobs_empresas, coleção empresas.
- Vagas: banco 8jobs_vagas, coleção vagas.
- Candidatos: banco 8jobs_candidatos, coleção candidatos.
- Candidaturas: banco 8jobs_candidaturas, coleção candidaturas.

Os quatro serviços usam Mongoose e a variável MONGODB_URI nos arquivos .env
locais. Os arquivos .env.example mostram a configuração padrão para MongoDB
local em mongodb://localhost:27017.

Os vínculos entre bancos são feitos guardando IDs, não copiando nem acessando
coleções remotas:

- Uma vaga guarda empresaId.
- Uma candidatura guarda candidatoId e vagaId.

Regras relevantes:

- Vaga exige título, descrição, salário não negativo, modalidade, cidade e
  empresaId. O status começa como ABERTA e pode ser FECHADA.
- Candidato exige nome, e-mail, telefone e cidade; o e-mail é único.
- Candidatura só pode apontar para candidato existente e vaga aberta. O status
  inicial é ENVIADA; outros valores possíveis são EM_ANALISE, APROVADA e
  REJEITADA.
- Cada par candidatoId + vagaId é único, impedindo candidatura duplicada.
- Os models registram createdAt e updatedAt automaticamente.

database/conexao.js centraliza os nomes dos quatro bancos para os scripts de
criação e popularização. npm run db:criar cria as coleções e índices. npm run
db:popular adiciona dados de exemplo sem sobrescrever registros existentes.
O argumento --zerar apaga os registros dos quatro bancos antes de inserir os
exemplos; use-o somente quando quiser realmente apagar os dados existentes.


6. COMO EXECUTAR NO WINDOWS

Pré-requisitos: Node.js e MongoDB Server instalados. O MongoDB Compass é a
interface visual; quem guarda os dados e escuta na porta 27017 é o MongoDB
Server. No Compass, conecte usando mongodb://127.0.0.1:27017.

No PowerShell, se o comando npm for bloqueado pela política de execução de
scripts, use npm.cmd nos exemplos abaixo. No Git Bash, use npm normalmente.

Na pasta raiz do projeto, instale todas as dependências do frontend e dos quatro
serviços de uma vez. O npm workspaces está configurado na raiz:

    npm.cmd install

Para iniciar tudo, use um único comando na raiz:

    npm.cmd run dev

O comando cria os arquivos .env que estiverem faltando, verifica se o MongoDB
está acessível e inicia os quatro serviços, o gateway e o frontend. Os arquivos
.env existentes não são sobrescritos. Pressione Ctrl+C para encerrar todos os
processos. O frontend normalmente fica em http://localhost:5173 e o gateway em
http://localhost:3000.

Para criar os bancos, coleções e índices e inserir dados de exemplo, rode estes
comandos uma vez (ou quando precisar):

    npm.cmd run db:criar
    npm.cmd run db:popular

Se o PowerShell bloquear npm.ps1, use npm.cmd como nos exemplos. No Git Bash,
use npm e npm run dev normalmente.


7. TESTES

Os testes Jest dos microserviços ficam em services/*/test. Na raiz, rode:

    npm.cmd test

Os testes Cypress estão em cypress/e2e e cobrem navegação, consulta e seleção
de vagas e candidatura. Eles usam uma API simulada em
cypress/support/fakeApi.js; para esses testes, não é preciso iniciar MongoDB,
microserviços ou gateway. Inicie o frontend e, em outro terminal, rode:

    npm.cmd run dev:frontend
    npx.cmd cypress open


8. ARQUIVOS IMPORTANTES

- server.js — gateway Express.
- frontend/src/App.jsx — rotas do React.
- frontend/src/services/ — chamadas HTTP do frontend.
- services/*/src/routes/ — rotas HTTP dos microserviços.
- services/*/src/controllers/ — regras e respostas HTTP.
- services/*/src/models/ — estrutura e validação dos documentos.
- services/*/src/config/database.js — conexão de cada microserviço ao MongoDB.
- services/*/src/clients/ — chamadas HTTP entre microserviços.
- database/ — scripts de criação dos bancos e dados de exemplo.
- cypress/ — testes de ponta a ponta com API simulada.
